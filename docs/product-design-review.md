## 流程检查

1. 框选 → 标注工具条：正常。主操作保留纯对号；按钮带悬停提示；工具条有明确分组。工具条高度按实际内容变化，620×480 展开色板的边界由测试覆盖。
2. 文字输入与样式：正常。10 源像素内边距、文字色、背景色、字形和字号共享到导出模型。文字 Enter 换行，Ctrl / Command + Enter 完成。
3. 线条滑块：发现并修复一处焦点问题。点击滑块原先只改变数值，不主动接收键盘焦点；现点击后可直接用左右键微调。同时修正禁用滑块的可访问性状态，禁用时不再暴露增减操作。
4. 模糊与导出：自动化检查正常。模糊只作用底图，文字、箭头、方框维持上层；保存取消与剪贴板失败保留会话；确认前不复制。

## 视觉与交互

- 字体：中性系统文字、中文回退字体；测试预览加载真实中文字体。当前渲染未发现文字被工具条裁切。
- 布局：工具条宽度上限 480 逻辑像素；内容自动测高，窄窗口内有最大高度及滚动约束。
- 配色：中性明暗面板、系统蓝主操作；色板选中态有背景指示。截图不能证明所有组合符合对比度标准。
- 图标：使用 Cupertino 图标库；保持统一字号与密度。
- 文案：确认复制、取消和文字编辑提示与实际快捷键一致。

## 验证与限制

flutter analyze 无问题；flutter test 的 9 项检查全部通过；合成组件渲染检查通过。新增滑块检查明确断言“点击后直接按左键减少 0.5”，避免仅检查不抛异常。

Product Design 的完整 audit 流程要求浏览器／Computer Use 采集实际产品流程，本会话没有能操作该 Windows 原生界面的对应采集工具，因此不宣称完成完整插件流程审计。这里展示的是 Flutter 测试渲染与交互验证。屏幕阅读器、中文输入法候选窗及 macOS 原生权限、签名和显示器行为仍需真机验收。

四边定位更新：原生层返回每块显示器在截图中的实际像素边界；工具栏选择与选区重叠面积最大的单块显示器，不使用整片虚拟桌面作为安全区域。每次布局直接测量当下内容尺寸，依次寻找选区下、上、右、左的可用位置；放不下时覆盖选区的一部分，但保持尺寸并约束在当前显示器内。选区靠边仅重新定位，宽高约束与距离屏幕边缘无关。取消了可能跨越屏幕边界的位置补间动画，保留面板内容与按钮动画。自动化检查覆盖两块屏幕各四角、文字与色板展开的中间帧，以及竖屏和上下错位显示器布局。
